# Proof

Everything margin claims about steering a live agent, demonstrated rather than described.
Reproduce with `bash research/live_proof.sh /tmp/proof`.

## The claim

A rating pressed while an agent is working reaches it mid-run and changes what it does next,
with nothing typed and no turn interrupted.

## The test

Deliberately behavioural. The agent is never told feedback exists, is never asked whether it
received anything, and its self-report is not evidence of anything. Only its tool calls
count.

1. Give the agent a repetitive eight-step task: count the `.txt` files in eight directories,
   one shell command each, in order.
2. Let it run. It picks its own way of counting.
3. After the second command, record a rejection naming a replacement form no agent picks
   unprompted: `[System.IO.Directory]::GetFiles(path, '*.txt').Length`.
4. Compare the commands before and after.

The rejection is written exactly as the TUI writes it when you press `D` and type a reason.

## The result

Run on 2026-08-20, Claude Code 2.1.233, Haiku 4.5, Windows 11.


The agent switched at the first opportunity after the rejection, finished the task, and
never mentioned it. It did not stop, did not acknowledge, did not ask for confirmation.

## What it took to get an honest result

Three earlier runs failed, and each failure is worth keeping because each is a real property
of the system.

**Run 1 — the feedback did not apply.** The note said "do not use `ls`, use `find`". The
agent was on Windows using PowerShell and had never used `ls`. It ignored the advice
entirely and kept going.

That is the correct behaviour, and it is the over-correction guard working: a rejection that
does not match what the agent is doing should not derail it. But it makes a useless demo, so
the note now matches the platform the agent is actually on.

**Run 2 — the target form was one the agent already used.** The note asked for
`(Get-ChildItem …).Count`, and that run happened to pick that form for command 1 as well.
Nothing to observe. The replacement is now something no agent chooses unprompted, so a
change is unambiguous rather than luck.

**Run 3 — `--output-format stream-json` does not surface hook context.** The signal was
delivered, `delivered.jsonl` recorded it, and `margin-signal` appeared nowhere in the stream
and the behaviour never changed.

This is a genuine limitation and it is not documented anywhere. Hook `additionalContext`
reaches the model in a normal interactive or `-p` run, and does not appear in the
`stream-json` event stream. The proof now runs the agent the way a person runs it, and reads
the commands back out of the transcript file rather than the stream.

If you are building on Claude Code hooks and testing with `stream-json`, this will cost you
an afternoon.

## The signal that was delivered

Produced by the same `inject::render` the hook calls, so this is the payload, not a retelling:

```
<margin-signal kind="runtime_telemetry" count="1">
Generated by margin, not written by the user. The user reacted to specific moments of this
run from a side channel. This is not a conversational turn: it expects no reply, no
acknowledgement, and no pause in the current task.

1. REJECTED — the user reacted negatively to this
   at 11:50:31 — "(Get-ChildItem -Path alpha -Filter *.txt).Count"
   takeaway: stop doing this; instead: stop using Get-ChildItem for this; every remaining
   count must use [System.IO.Directory]::GetFiles(path, '*.txt').Length instead

These are soft priors from a small sample. Fold them into how the rest of this session
proceeds; do not overhaul an approach that is otherwise working, and do not restart work
already done. Continue the task now. Do not comment on this block unless the user asks what
changed.
</margin-signal>
```

## What this proves, and what it does not

Proved:

- a rating recorded mid-run reaches a live agent's context
- the agent acts on it at its next tool call
- it does not stop, acknowledge, or ask
- delivery happens exactly once, recorded in `delivered.jsonl`

Not proved, and not claimed:

- that a rejection with **no** written reason steers as reliably. It should not, by design:
  a bare tap only suppresses the exact rated action.
- that this holds on larger models under long context. Only Haiku 4.5 was measured here.
- anything about Codex injection, which is not implemented yet.
